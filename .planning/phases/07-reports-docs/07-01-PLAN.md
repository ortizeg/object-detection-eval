<objective>
Close the REPORT-01 accuracy-data gap. Neither `scripts/run_benchmark.py` nor
`scripts/run_bootstrap_gate.py` currently writes its result to disk — both only log a table and
exit. This plan adds a `--write-results PATH` flag to each (a thin persistence addition to the
existing `main()`, not a new script), then has the executor run them to produce and commit three
small accuracy JSONs. Those files become the committed, tamper-evident source every accuracy
table in the Phase 7 reports is generated from.

Purpose: REPORT-01's guarantee ("a published number cannot drift from the data that produced it")
is only real if the data exists as a committed file. The VLM and latency results files already
exist (Phases 5/6); the accuracy side is the one missing input. This plan produces it using the
same executor-run-then-commit pattern, with all required artifacts (`source_repo` `.deploy_comparison/`,
the external `yolox` root, the basketball test GT) present on this machine now. (REPORT-01)
Output: `--write-results` on both scripts, offline write-path tests, and three committed JSONs
under `benchmarks/basketball/results/accuracy/`.
</objective>
