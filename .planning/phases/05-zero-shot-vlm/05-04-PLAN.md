<objective>
Port the VLM auto-labeling task into `src/object_detection_eval/annotate/`. Unlike the source (which wrote one self-contained DetectionAnnotation JSON per image), the target task emits a SINGLE COCO annotation file over the image directory that loads back through `load_coco_gt()` without error — the exact round-trip VLM-03 requires. It runs a VLM (Gemini by default) over a directory of unlabeled images and writes the aggregated COCO JSON.

Purpose: Demonstrates the "if zero-shot detection is weak, can a VLM at least *label*?" capability behind the `[vlm]` extra, with a closed COCO round-trip as the acceptance test. (VLM-03, VLM-04)
Output: `annotate/{__init__,coco_writer,vlm_task}.py` + a mocked round-trip test through `load_coco_gt`.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| local → Gemini API | Auto-labeling sends images to Google and parses returned boxes |
| VLM output → COCO file | Untrusted label strings/boxes are written into a COCO JSON consumed downstream |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-05-11 | Tampering | Out-of-taxonomy labels from the VLM | medium | mitigate | GeminiInferencer already drops labels with no eval mapping; coco_writer only emits category_ids from the provided id->name map |
| T-05-12 | Information Disclosure | Gemini key reuse | high | mitigate | Task constructs GeminiInferencer, which reads the key from env only (see 05-02 T-05-04); the task never accepts or logs a key |
| T-05-13 | Denial of Service | Corrupt/unreadable image in the dir | low | mitigate | Preserve the per-image try/except that logs and continues, so one bad file does not abort the batch |
</threat_model>
