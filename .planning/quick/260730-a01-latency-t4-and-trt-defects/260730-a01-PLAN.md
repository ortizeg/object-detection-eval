# Quick Task 260730-a01: Land dedicated-T4 latency + fix 3 TRT-workflow defects

Chunk (a) of 3. Chunks (b) SmolVLM2 purge + registry and (c) report rewrite follow
separately; (c) depends on this chunk's numbers.

## Background

`trt_fp16_toboxes.json` / `trt_fp16_gpuonly.json` were measured on a **shared
vast.ai T4**. Contention inflated every number (DEIM-M read 43.00 ms) and drove
the report's conclusion that the source 4.0–7.1 ms band was "NOT portable across
T4 instances."

A dedicated GCP T4 (`n1-standard-8` + 1×T4, us-central1-a, persistence mode on,
SM clock locked to 1590 MHz, sole tenant, TensorRT **10.3.0** — the same version
as the shared run, so instance is the only changed variable) re-measured all 7
models on **md5-identical** ONNX artifacts.

Result: DEIM-M 43.00 → **6.61 ms** (source T4 recorded 6.56). The "not portable"
conclusion was wrong — it was contention. 4 of 7 models now land inside the
published band; RF-DETR (7.71), RT-DETRv2 (7.93) and RTMDet (8.19) sit modestly
above it.

## Tasks

### Task 1 — Fix `resolve_trt_version()` (scripts/build_trt_engines.py)

- **Bug A (misattribution):** prefers `import tensorrt.__version__` over the
  `--trtexec` binary that actually builds the engines. In the dedicated run the
  pixi env held **10.16.1.11** while the builder was **10.3.0**, so the emitted
  provenance was wrong.
- **Bug B (regex):** `TensorRT[^\d]*([\d.]+)` against the NGC banner matches the
  *container tag* `24.08`, because the first `TensorRT` occurrence is the ASCII
  banner and the next digits belong to `NVIDIA Release 24.08`.
- **Action:** query the `--trtexec` binary first; parse `TensorRT Version X.Y.Z`,
  else the packed `[TensorRT v100300]` token; fall back to the Python binding only
  when the binary yields nothing.
- **verify:** `pytest tests/scripts/test_build_trt_engines.py`
- **done:** version derives from the binary in use; `24.08` is never returned.

### Task 2 — Replace both latency results files

- New medians/p99 from the dedicated run; `trt_version` corrected to `10.3.0`.
- `reproducibility.status` → `dedicated_instance_measured` (no longer
  `manually_measured`), label states instance, clocks and TRT version.
- `second_run` repurposed to record the **superseded** shared-instance run and
  name contention as the cause — the measurement is kept, not deleted.
- RTMDet-M `model_only` records `build_status: failed`: its mmdeploy `end2end`
  export carries a pre-NMS `TopK` whose K exceeds TensorRT's 3840 limit. Expected
  (that is why the graft strips it), not a regression — its `to_boxes` number is
  valid, only its on-GPU NMS delta is unavailable.
- **verify:** `pytest tests/report/`
- **done:** both files load through `LatencyResult` and carry `10.3.0`.
