# Summary — 260731-d01 (chunk d)

## Grounding-DINO: 99.7% of detections were one class

533 detections per image, **49,935 of 50,103 labelled `person`**, and the
basketball found **once in 94 images**. Two independent causes, both fixed:

1. **`text_threshold: 0.01`** → **`0.25`** (Grounding DINO's published default).
   At 0.01 nearly every text token activated, so the processor returned a label
   spanning the *entire caption* for almost every box. A low **box** threshold is
   correct — mAP integrates the full PR curve — but a low **text** threshold is
   not, because it destroys class assignment rather than extending the curve.
2. **`_resolve_label` guessed.** Given a multi-class label it returned the class
   name appearing *earliest in the string* — i.e. the caller's **prompt
   ordering**, not the model's opinion. Combined with (1) that assigned nearly
   everything to the first-listed class. Now an ambiguous label is **dropped**.

Guessing here does not degrade gracefully: it manufactures a class distribution
out of prompt ordering, which is worse than returning nothing.

## Florence-2: wrong operating mode

Ran with `task: "<OD>"` — Florence-2's **closed-vocabulary** mode, which can only
emit its own pretrained label set and **cannot be steered by `classes` at all**.
923 of 924 detections were `person`. Now `<CAPTION_TO_PHRASE_GROUNDING>`, with
`caption` threaded through the manifest and factory, plus a `bboxes_labels` key
fallback so `<OPEN_VOCABULARY_DETECTION>` also parses.

## Prompt parity

Grounding-DINO and Florence-2 now receive the same domain vocabulary OWLv2 had.
**OmDet-Turbo is NOT equalised** and still runs the generic COCO list — an
honest remaining asymmetry, recorded rather than quietly ignored.

## Targets invalidated on purpose

`grounding_dino` and `florence2` have `expected_map5095: null`. Their published
0.147 / 0.104 came from the broken configuration and are not worth reproducing.
This consumes the null-target capability deliberately retained in chunk (b).

## Newer methods surveyed (2026-07-31)

- **API-only, and stronger than anything here:** DINO-X Pro (59.8 AP
  LVIS-minival), Grounding DINO 1.5/1.6 Pro (55.7 AP). Both far exceed the
  `grounding-dino-base` checkpoint tested, but they cost money per run and make
  a row non-reproducible without a key — same category as Gemini.
- **Open-weights gap worth closing:** **YOLO-World** (Apache-2.0, ~35.4 AP
  zero-shot LVIS, real-time) and **YOLOE**. YOLO-World is the notable omission —
  permissive, fast, open-vocabulary, directly comparable to this roster.
  ⚠️ **YOLOE-26 builds on YOLO26 and likely inherits AGPL**; check before adopting.

## Tests

Three existing tests **asserted the old buggy behaviour**
(`test_concatenated_label_picks_first_match`,
`test_large_box_concatenated_falls_through_to_person`). Rewritten to assert the
drop, each carrying the reason. Added coverage for the exact collapse mode
(whole-caption label), for unambiguous partial matches still resolving, and for
the two manifest invariants (text_threshold not at the collapse value;
Florence-2 not on `<OD>`).

`pytest tests/` default env: **314 passed, 8 skipped**. ruff + mypy clean.

*Note:* the full suite in the **`vlm`** env shows 5 failures in the torch-free
guard tests — **pre-existing**, reproduced on clean `main` (390 passed there vs
393 here, same 5). They are an artifact of running the whole suite where torch
is installed; CI runs the default env.
