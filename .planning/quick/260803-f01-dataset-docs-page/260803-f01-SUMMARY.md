# Summary — 260803-f01 (chunk f)

`docs/dataset.md` now documents the dataset, with every table emitted by
`scripts/generate_report.py` and covered by its `--check` drift gate.

## The design problem, and how it was solved

The repo's rule is that no published number is ever typed by hand. But the
dataset lives **outside the checkout** and CI has no copy of it, so a generator
that read the dataset directly would make the drift gate unrunnable in CI —
which is where it matters.

Solved by copying the VLM precedent exactly:

```
raw dataset ──(local, reads GT)──▶ committed JSON ──(GT-free)──▶ tables
            write_dataset_stats.py   results/dataset/   report/{loaders,tables}
                                     dataset_stats.json  generate_report.py --check
```

`write_dataset_stats.py` is the sole reader of the dataset. The committed JSON
is 7.4 KB. The generator, its `--check` gate, and every test read only that
file — proven by a test that renders all nine dataset slots in a suite with no
dataset present.

### The wrinkle, resolved rather than papered over

Nothing in CI can prove the committed JSON still matches the real dataset; CI
cannot see the dataset. That is the same gap `vlm_metrics_merged5.json` already
has. Rather than leave it unstated, `write_dataset_stats.py --check` recomputes
and diffs against the committed file, so the gap is a **runnable local gate**.
The page documents it in "Reproducing these numbers" rather than hiding it.

Two invariants are also enforced at write time instead of asserted in prose:
the set of categories carrying annotations must equal the `raw10` class list,
and every raw category must resolve to a `merged5` class. A category appearing
or disappearing breaks the build rather than quietly changing a total.

## Verified facts (re-derived, not taken on trust)

All confirmed against the dataset:

| | images | clips | annotations |
|---|---|---|---|
| train | 464 | 15 | 9,552 |
| valid | 96 | 3 | 1,953 |
| test | 94 | 3 | 1,980 |
| **all** | **654** | **21** | **13,485** |

654 images, all 1920×1080, 21 clips, 3 games, 10 raw categories → 5 eval
classes. Zero shared clips between any pair of splits; all three pairs share
all three games.

One refinement worth recording: at the *quarter* granularity the clip key
encodes, train spans 5 game-quarters and valid/test 3 each. At the **game**
granularity (quarter dropped) there are exactly 3 games and every split uses all
3 — which is the claim the page makes, and it holds.

Test-split class imbalance (merged5): `player` 944 (47.7%), `number` 567,
`referee` 280, `ball` 96 (4.8%), `rim` 93 (4.7%). Cross-checked against
`reproduction_640_merged5.json`: **6 of 7 models score exactly 1.000 AP@50 on
`rim`**, while `ball` spans 0.499–0.887. The page states this qualitatively and
points at the report table rather than hard-typing a count that could go stale.

## Decisions

- **`clip_key` promoted out of `scripts/run_clustered_bootstrap.py`** into
  `src/object_detection_eval/data/clips.py`. Two copies of that regex would be a
  drift source in exactly the dimension this page is about. Output format is
  unchanged — verified byte-identical across all 654 filenames — so the
  committed `bootstrap_clustered_7models.json` cluster keys still match. Added
  `game_id()` for the coarser game-level grouping caveat 2 needs.
- **The dataset page joined the `generate_report` registry** rather than getting
  its own script. `build_registry` gained a `docs_dir`: a document belongs in
  the registry whenever it publishes numbers, wherever it lives. The existing
  `test_committed_reports_are_not_drifted` is registry-driven, so it picked the
  page up automatically.
- **Verdicts are derived, never hard-coded.** "The splits are clip-disjoint" is
  emitted because zero pairs share a clip. A test flips each fixture to the
  opposite answer and asserts the verdict flips — a hard-coded sentence would
  pass the happy path and stay silently wrong exactly when it mattered.
- **`allowed-confusables = ["×"]`** in `pyproject.toml`. The renderers emit
  prose read by humans, where `1920×1080` is correct typography.
- **Did not touch either benchmark report.** PR #15 is open against the VLM one;
  cross-links went into `README.md` and `docs/methodology.md` instead.
