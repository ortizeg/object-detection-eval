# Plan — 260803-f01: maximise zero-shot VLM performance by disciplined ablation

Chunk (f). Continues 260801-e01 (PR #15), which equalised the *prompt* across
the five open-weights VLMs. Everything else about their configuration is still
whatever the first commit happened to pick. This task finds out how much of the
zero-shot ceiling is config and how much is the models.

## The one non-negotiable

**Every exploratory measurement runs on the 96-image `valid` split. Never
`test`.** Selecting a setting on the split the report publishes turns the
published number into the maximum over N draws. `search_vlm_prompts.py` already
enforces this in both the schema and the CLI; anything built here inherits the
same refusal. `test` is run exactly once, at the end, for the single chosen
configuration.

## Method

One element at a time. Measure on val, record the delta against the immediately
preceding accepted configuration, **keep it only if it helps, revert it if it
does not**, then move on. Failures are recorded with the same weight as wins —
the report already leans on several negative results and this extends them.

The running table (model × element × val mAP@50:95 × delta × kept/reverted) is
committed as a machine-readable artifact plus a generated Markdown view, not
narrated in prose.

## Efficiency decision: cache raw detections, sweep post-processing offline

NMS IoU, `box_threshold` and the singleton `top_k` are all *post*-processing.
Re-running a 96-image forward pass per value would cost hours for measurements
that are algebraically determined by one pass. So each (model, checkpoint,
vocabulary) is run ONCE with NMS disabled and a floor `box_threshold`, its raw
detections cached, and the post-processing grid then swept in seconds.

This is exact, not an approximation, for greedy NMS: a lower-scoring box can
never suppress a higher-scoring one, so NMS-then-threshold and
threshold-then-NMS produce the same kept set. The harness asserts this
equivalence against a live run before any cached number is trusted.

## Candidate elements, in the order they will be tried

1. **NMS IoU threshold** — currently unequalised (OWLv2 0.3, Grounding-DINO and
   YOLO-World 0.5, OmDet-Turbo defaulted to 0.5 without ever being declared,
   Florence-2 has no NMS at all). Sweep per model.
2. **`box_threshold`** — 0.01 everywhere, never checked. Sweep per model.
3. **Singleton `top_k`** — re-confirm 3 is still right once NMS/threshold move.
4. **Checkpoint variants** — Florence-2 `-large` vs `-large-ft` (an incidental
   val run suggested ~+0.029 for the non-ft base), Grounding-DINO tiny/base,
   OWLv2 ensemble vs finetuned, YOLO-World s/m/l/x. A checkpoint change
   invalidates the vocabulary choice, so any winner re-runs the full 6-candidate
   search — equal effort applies to the new checkpoint too.
5. **Per-class best-of vocabulary** — the existing search shows different
   candidates win different classes for the same model (OWLv2: `player` 0.833
   under c1, `referee` 0.455 and `number` 0.472 under c5). Vocabularies do not
   compose — the same word scores differently beside different neighbours — so
   this is a 7th candidate to *measure*, not an arithmetic combination.
6. **Input resolution / tiling** — overlapping tiles merged by NMS. The only
   lever that plausibly targets `rim`, `ball` and `number` together. Most work,
   most upside, done last because it is the only one needing new inference code.
7. **Florence-2 NMS + confidence** — it emits every box at confidence 1.0 and
   applies no NMS, so within an image the scorer cannot rank its detections at
   all. Cheap to test, structurally distinct from element 1.

Ensembling / weighted box fusion is explicitly out of scope unless everything
else lands: it is not a per-model result and would need its own reporting.
