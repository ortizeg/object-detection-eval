## Provider docs fetched (2026-10-27) and field names adopted

Fetched with curl (no WebFetch tool was available in this session) and cross-checked against the installed SDK `model_fields`.

- **OpenAI** (<https://developers.openai.com/api/reference/python/resources/chat/subresources/completions/methods/create>, <https://developers.openai.com/api/docs/guides/reasoning>; openai-python 3.19.2): `usage.prompt_tokens`, `completion_tokens`, `total_tokens`, `completion_tokens_details.reasoning_tokens`, `prompt_tokens_details.cached_tokens`. Reasoning is a subset of `completion_tokens` (SDK docstring: "like reasoning tokens, these tokens are still counted in the total completion tokens for purposes of billing"; the guide: "billed as output tokens"). Request id: `completion._request_id`. **Doc vs SDK discrepancy:** the installed SDK's `PromptTokensDetails` also has `image_tokens` and `text_tokens` (and `cache_write_tokens`), which the docs page example omits. The SDK names are read; they are `None` when the API does not send them.
- **Anthropic** (<https://docs.claude.com/en/api/messages>, redirects to platform.claude.com; <https://docs.claude.com/en/docs/build-with-claude/extended-thinking>; anthropic 1.13.0): `usage.input_tokens`, `output_tokens`, `cache_creation_input_tokens`, `cache_read_input_tokens`, `service_tier`, `output_tokens_details.thinking_tokens` ("Always <= output_tokens", a subset). `input_tokens` excludes cache reads and writes, so the logged input is the sum of the three. No image/text split is reported. Docs and SDK agree.
- **Gemini** (<https://ai.google.dev/api/generate-content#UsageMetadata>, <https://ai.google.dev/gemini-api/docs/pricing>; google-genai 1.75.0): `prompt_token_count` (includes cached content), `cached_content_token_count`, `candidates_token_count`, `thoughts_token_count`, `total_token_count` ("prompt + tool-use prompt + thoughts + response candidates", so thoughts are separate), `prompt_tokens_details` (modality, token_count) for the image/text split; request id `response_id`, served model `model_version`. Pricing page: "Output price (including thinking tokens)". Docs and SDK agree.
- **DeepDataSpace V2 task API** (<https://github.com/IDEA-Research/DINO-X-API> README, open-source `dds-cloudapi-sdk` `tasks/v2_task.py`; the cloud docs site is a script-rendered SPA and was not fetchable): no cost or consumption field is documented on trigger or task-status payloads, so `cost_reported` is null for DINO-X. The record keeps `task_uuid` and the poll count (plus filtered scalar status fields, never `result` or any key containing token/key/image/error/msg).

- OpenAI's SDK exposes `prompt_tokens_details.image_tokens` / `text_tokens`, absent from the docs page example. Read from the SDK, null when unsent.

**4. [Rule 2 - correctness] Extra safety in the aggregator**
- Refuses a run with a record whose `image_id` is not one of the run's frames, a manifest whose `frame_timings` do not cover exactly its frames, and runs with mixed `--workers`. Not in the plan's list, but each would put a wrong number in the report.

**5. [Plan clarification] `--max-frames` is allowed only with `--run proj`**
- Runs 1 and 2 always use all 20 frames. The plan only required `proj` to demand `--max-frames`; allowing it on runs 1 and 2 would let a truncated run enter the statistics under a full-run label, so the driver refuses it.
